### 🚀 현빈의 핵심 전략 요약 및 근거

**1. 초기 진입 순서 (MVP 관점): Model 2 $\rightarrow$ Model 1 $\rightarrow$ Model 3**
*   **이유:** 가장 빠르게 구현 가능하고, 데이터가 이미 존재하여 가치를 증명할 수 있는 **Model 2(Advanced Report)**로 시작해야 합니다. 이 보고서는 *데이터를 해석하는 지능적인 레이어* 역할을 하여 사용자 만족도를 높이고 신뢰를 구축합니다.
*   **신뢰 확보 후:** 사용자가 서비스에 익숙해지고 트래픽이 늘어나면, 가장 확실한 매출원인 **Model 1(Booking)**을 API 연동으로 도입하여 수익성을 즉시 극대화합니다.
*   **성장 단계:** 충분한 사용자 기반과 신뢰가 쌓인 후, 객단가를 높여줄 **Model 3(Concierge Package)**를 통해 시장 지배력을 확보합니다.

**2. 가장 강력한 KPI: 구매 전환율 ($\text{P}CR$)과 첨부율 ($\text{A}R$)**

## III. 와이어프레임 및 UX 플로우 상세 설계 (The What)

이 Paywall Mockup은 **1500px 너비 기준의 단일 섹션**으로 구성됩니다.

### A. [Step 1: 무료 결과 노출 영역] - 신뢰 구축 (Trust Building)
*   **목적:** 사용자에게 '유용하다'는 느낌을 먼저 제공하여, 유료 기능이 없을 때 실망감을 느끼게 만듭니다.
*   **레이아웃:** 일반적인 정보 카드 형태를 유지합니다.
*   **핵심 요소:** 코다리 API 스키마의 **일부 데이터만** 성공적으로 보여줍니다.
    *   예: '최적 이동 시간 (평균)'은 노출하나, '비용 절감 시뮬레이션' 항목은 비워둡니다.

### B. [Step 2: Paywall Trigger] - 결핍 유발 및 경고 (The Hook)
*   **위치:** 무료 결과 섹션의 끝, 또는 사용자가 가장 기대하는 핵심 지표 바로 아래에 배치합니다.
*   **시각적 처리:** **'⚠️ Advanced Analysis Locked'** 라는 경고 박스를 삽입합니다.
    *   **디자인 요소:** 배경색은 Warning Red 계열로 채도 높게 처리하며, 모서리에는 뾰족한 느낌을 주어 '위험/경고'의 시각적 메시지를 강화합니다.
    *   **텍스트 내용 (Writer v1 활용):** "⚠️ **[Hidden Cost 경고]** 이 경로만으로는 A 옵션이 최적인지, B 조합이 더 저렴한지는 판단할 수 없습니다."
    *   **효과:** 잠금 아이콘(🔒)을 사용하고, 아이콘 주변에 희미하게 깜빡이는 애니메이션 효과를 적용하여 긴급성을 부여합니다.

### C. [Step 3: Paywall CTA 섹션] - 해결책 제시 및 구매 유도 (The Conversion)

### 📄 Advanced Report Backend API 명세 (v1.1 - Paywall 강화)

**목표:** 사용자 입력 데이터(Input Trip Parameters)를 받아 '경제적 최적 대안 제시'라는 핵심 가치를 계산하고, 이 로직을 기반으로 무료/유료 정보가 구분된 JSON 객체를 반환하는 것.

#### 1. API Endpoint 정의
*   **Endpoint:** `/api/v1/advanced-trip-report` (POST)
*   **Description:** 여행 경로 데이터를 받아 비용 효율성 및 시간 최적화를 분석한 보고서 데이터를 생성합니다.

#### 2. 요청 파라미터 (Request Body Schema)
| 필드명 | 타입 | 필수 여부 | 설명 | 예시 |
| :--- | :--- | :--- | :--- | :--- |
| `origin` | String | O | 출발지 명칭 또는 좌표계(WGS84). | "Incheon Airport" |
| `destination` | String | O | 도착지 명칭 또는 좌표계(WGS84). | "Gangnam Station" |
| `date` | Date String | O | 여행 날짜 (요일 정보 추출에 사용). | "2026-10-25" |
| `travel_type` | Enum | O | 이동 목적/유형 (예: 관광, 비즈니스 출장). | `"tourist"` |
| `budget_range` | Object | X | 사용 가능한 예산 범위. (`{min: number, max: number}`) | `{min: 50000, max: 100000}` |

## ⚠️ 핵심 기술 요구사항 및 예외 처리 (Critical Implementation Notes)

1. **[Hidden Cost] 로직 분리:** `Optimal Saving Potential` 계산 알고리즘은 반드시 독립적인 백엔드 모듈로 구현되어야 하며, 테스트 케이스를 통해 산출값이 일관되게 나오는지 검증해야 합니다.
2. **Funnel 제어 (서버 레벨):** 클라이언트가 유료 콘텐츠 필드를 요청할 때마다 서버는 `is_paid: true`를 반환하기 전에 반드시 사용자 인증 및 결제 상태(Subscription Status)를 체크하는 게이트웨이를 거쳐야 합니다.
3. **에러 핸들링:** 모든 API 호출은 표준 에러 응답 구조(`{"status": "error", "code": 400, "message": "구체적인 오류 메시지"}`)를 사용해야 하며, 특히 데이터 불충분이나 경로 비현실성은 사용자 친화적이고 구체적인 피드백을 제공해야 합니다.
