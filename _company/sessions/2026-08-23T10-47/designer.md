### 📐 Failure State Design Brief (3종)

#### 💡 1. [General System Failure] 와이어프레임: "데이터 처리 불가" 상태
*(Trigger: 503 Service Unavailable, API Gateway Timeout)*
가장 흔한 기술적 실패 상황입니다. 시스템 오류를 '잠시 데이터 로딩에 시간이 걸리는 복잡한 분석 작업'으로 포장해야 합니다.

**[디자인 원칙]**
*   기술 용어(Error Code) 사용 금지.
*   시스템이 현재 '작업 중'임을 강조하여 사용자에게 책임을 전가하지 않음.
*   사용자 액션(Action)을 제한적으로 제공하여 이탈 방지.

| 요소 | 내용 및 디자인 스펙 | 목적/효과 |
| :--- | :--- | :--- |
| **헤드라인 (H1)** | ❌ "현재 분석에 시간이 더 필요합니다." (Warm, 걱정하는 톤) | 기술적 실패를 '복잡성'으로 포장. |
| **서브 카피** | "요청하신 정보는 매우 방대하여 최적의 경로를 계산하는 데 시간이 소요됩니다. 저희 AI가 최고의 아카이브 데이터를 찾아 정리하고 있어요." | 서비스의 복잡도와 가치를 간접적으로 홍보. |
| **비주얼 요소** | 진행 바 (Progress Bar) 혹은 로딩 애니메이션: "최적화 중..." 문구와 함께 미세한 움직임 제공. | 사용자의 시선을 붙잡고 '기다릴 이유'를 만듦. |
| **CTA 1 (Primary)** | [✅ 메인 대시보드 돌아가기] (클릭 가능, 정상 작동 유도) | 즉각적인 이탈을 방지하고 서비스 재사용 유도. |
| **CTA 2 (Secondary)** | "나중에 다시 확인하시겠어요?" (재접속 유도 버튼/링크) | 시간 기반 리마케팅의 시작점 마련. |

#### 💡 2. [Data Deficit] 와이어프레임: "정보 결핍" 경고 상태
*(Trigger: Advanced Report Data 누락 또는 데이터 유효기간 만료)*
시스템은 정상 작동했지만, 사용자가 내린 결정에 필요한 핵심 정보가 부족할 때 발생합니다. 가장 위험한 실패 지점입니다.

**[디자인 원칙]**
*   '불충분함'을 '더 많은 가치'로 치환하여 판매 기회를 창출.
*   사용자의 현재 데이터 관점을 재정립하게 유도 (손실 인식).

| 요소 | 내용 및 디자인 스펙 | 목적/효과 |
| :--- | :--- | :--- |
| **헤드라인 (H1)** | ⚠️ [경고] 결정에 필요한 핵심 정보가 부족합니다. | 직설적으로 문제를 지적하며 사용자의 주의 집중. |
| **서브 카피** | "현재 보고서는 3개월 전 데이터를 기반으로 하고 있습니다. 이 시점의 교통비 변동 폭이나 숨겨진 로컬 비용을 고려한다면, 계획이 최적이 아닐 수 있습니다." | '손실'을 구체적인 시간/비용 개념으로 명시 (Loss Funnel 시작). |
| **시각 요소** | 🚨 Visual Alert Box: 경고 색상(Amber/Orange)과 함께 "데이터 유효성 만료" 표시. | 시선을 끌어 필수 정보를 인식하게 함. |
| **CTA 1 (Primary)** | [💎 Advanced Report 상세 분석 보고서 받기] (유료 결제 Funnel 진입 버튼) | 가장 강력하고 직접적인 수익화 액션 유도. |
| **CTA 2 (Secondary)** | "최신 아카이브 데이터를 미리 확인하기" (로그인/회원가입 유도) | 낮은 장벽의 리텐션(Retention) 활동을 유도. |

3.  **[Supporting Text]**: "최적의 여정은 실시간으로 변화합니다. 지금 필요한 것은 **'결정적인 정보의 업데이트'** 입니다."

#### 💡 3. [Pre-Conversion Failure] 와이어프레임: "데이터 연결 끊김" 상태
*(Trigger: Paywall 진입 직전, 클라이언트/서버 간 데이터 동기화 실패)*
가장 중요한 순간에 발생하는 실패입니다. 사용자는 이미 '결제'라는 문턱을 넘었기에 불안감이 극대화됩니다.

**[디자인 원칙]**
*   절대로 "오류"라고 말하지 않는다.
*   사용자의 **의도(Intent)**를 재확인시키고, 시스템이 실패한 것이 아니라 '데이터 전송에 문제가 발생했다'는 점을 암시한다.
*   신뢰 회복과 함께 결제 Funnel로 자연스럽게 복귀시키는 것이 목표다.

| 요소 | 내용 및 디자인 스펙 | 목적/효과 |
| :--- | :--- | :--- |
| **헤드라인 (H1)** | 🔄 잠시만요, 최종 정보를 연결하고 있습니다. | 사용자에게 '잠시의 지연'으로 인식시켜 긴장감 완화. |
| **서브 카피** | "가장 중요한 데이터 필드를 로딩하는 중입니다. 끊김 없이 최고의 결정을 내리실 수 있도록 데이터를 동기화합니다." | 현재 진행되는 액션이 매우 중요함을 강조하여 이탈 방지. |
| **비주얼 요소** | 🔄 Sync Icon + 애니메이션: "데이터 연결 최적화 중..." 문구와 함께 데이터 전송 시각화. | 시스템의 복잡한 백그라운드 작업처럼 보이게 함. |
| **CTA (Single)** | [✅ 자동 재시도] 버튼 (최대 3회까지 자동으로 클릭되도록 구현) | 수동 개입 없이 해결을 시도하여 사용자의 불편함을 최소화. |
| **Fallback 메시지** | (자동 재시도가 모두 실패했을 경우) "죄송합니다. 네트워크 연결 상태를 확인해 주시고, 다시 시도해 주세요." (기술적 오류가 아닌 환경 문제로 돌림). | 최종 단계에서 발생하는 오류는 외부 요인(사용자 기기/네트워크) 탓으로 돌림으로써 신뢰 유지. |
